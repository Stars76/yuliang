# EntropicEcho 额度聚合面板 — 功能说明书

本项目是一个**AI 账号额度聚合面板**。它把多个 AI 编码/模型服务的订阅额度、按量余额，统一拉到一个界面里展示：每个账号一张卡片，卡片里能看出「额度还剩多少」「多久重置」「是哪个套餐」。目的是让用户不用逐个登录各家的后台/CLI，就能集中对照所有账号的用量和周期。

> 本文件只描述「项目有哪些功能」，不涉及实现细节。要实现哪个端、怎么实现，见 `AGENT-PROMPT.md` 与 `PLAN-STANDALONE.md`。

---

## 一、整体形态

- 这是一个 **Web 面板**（浏览器访问），由服务器端 + 前端 SPA 组成。
- 所有查询都是**只读**的，面板只「看」额度，不产生任何模型用量。
- 数据来源是各家服务官方（或公开）的额度/用量接口，密钥由用户自己填写，面板加密保存。

---

## 二、支持的 Provider（额度来源）

面板聚合以下 AI 服务的额度信息，每个 Provider 对应一种接入方式与卡片类型：

| Provider | 类型 | 说明 |
|---|---|---|
| Codex / ChatGPT（CPA 直通） | 订阅额度 | 通过本机 CLIProxyAPI 枚举账号、读取用量窗口（5 小时 / 每周），含缓存快照兜底 |
| Codex（直连 ChatGPT） | 订阅额度 | 用 OAuth 设备码登录 ChatGPT 账号后读取用量窗口，access token 到期自动续期 |
| OpenCode（自动识别 Go / Zen） | 订阅额度 | 同一个 API Key 自动识别是 Go 还是 Zen；Go 显示 5 小时/每周/每月窗口，Zen 识别为 Zen 套餐 |
| Kimi For Coding | 订阅额度 | 5 小时 / 每周窗口 + 套餐名与会员等级 |
| Z.AI（智谱国际版） / BigModel（国内版） | 订阅额度 | 5 小时 / 每周 / MCP 月用量窗口 |
| Command Code | 订阅额度 | 5 小时 / 每周 / 每月窗口，自动识别套餐（如 GOAT=月 $10，限额 $14/$35/$70） |
| Ollama Cloud | 订阅额度 | 5 小时 / 每周 / 每月窗口 |
| DeepSeek | 按量余额 | 只剩余额（总/赠送/充值），无订阅额度 |
| sub2api（自建中转实例） | 额度或余额 | 额度限额模式显示总额度 + 5小时/每日/每周；订阅模式显示每日/每周/每月；钱包模式显示余额 |
| New API / One API（自建站） | 按量余额 | 余额 + 已用 |

每个 Provider 暴露的卡片形态由数据决定：**订阅额度类**画进度条/圆环 + 用量 + 重置倒计时；**纯余额类**只放大显示数字。

## 三、仪表盘（核心界面）

顶部一排统计 + 下方账号卡片网格。

### 顶部统计
- 账号总数、正常数量、异常数量。
- 整体健康度（正常的占比条）。

### 账号卡片
- **品牌图标 + 别名**，右上角标注数据来源（`live` 实时 / `cache` 快照）。
- **套餐标签**（如 GOAT、Pro、Go、Zen、plus 等，能识别就显示）。
- **额度窗口**：名称（5小时 / 每周 / 每月 / 每日 / MCP(月) 等）+ 剩余百分比 + 重置倒计时。
  - 进度条 / 圆环 / 嵌套环三种可视化，可一键切换。
  - 颜色随「已用比例」变化（安全=绿、偏黄、告警=红）。
  - 长周期窗口（≥1 天）额外显示具体重置日期（几月几号几点）。
- **纯余额卡**：只显示「可用余额」大数字 + 币种。
- **错误状态**：凭证过期 / 被限流 / 上游变更 / 不可用，都如实显示原因，绝不伪造额度。
- **上次刷新时间**显示在卡片脚注。

### 视图与排序
- **分组 / 总览** 两种显示模式随意切换：
  - 分组：按 Provider 分组展示，每个分组可**收起/展开**。
  - 总览：所有账号**无分组紧凑排**，卡片等高。
- **拖拽排序**：分组模式下拖拽分组头调整分组先后；总览模式下拖拽卡片调整账号顺序。排序偏好会被记住。

### 刷新
- 手动「刷新」按钮，一键全量刷新。
- 「自动刷新（5 分钟）」开关。
- 单账号重试按钮。
- 服务端对每账号有内存缓存（≥60 秒），上游失败按指数退避，不会频繁打上游。

### 进度显示方式
- 条形（默认）/ 圆环 / 嵌套环，一键切换并记住偏好。

## 四、凭证管理

- **添加凭证**：选 Provider → 填该 Provider 需要的密钥/地址（表单由 Provider 元信息驱动，每个字段有必填/隐藏/占位提示）。别名可选。
  - Codex（直连）为 OAuth 设备码登录，无需手填 access token / account ID。
  - 其它 Provider 手动填写 API Key / 实例地址。
- **编辑**：修改别名。
- **删除**：移除该账号，不可撤销。
- **Codex 账号选择**（CPA 模式）：列举本机 CPA 里的全部账号（脱敏邮箱），勾选要展示的账号并起别名，一次可勾选多个。
- **密钥不回显**：界面与 API 都不返回密钥内容（连脱敏片段都没有），密钥只用于服务器取数。

## 五、账户与安全（多用户服务器版才有）

单机版会砍掉这部分，这里列出便于对照：

- **注册 / 登录 / 登出**：主密码登录，服务端会话（12 小时滑动过期，HttpOnly + Secure + SameSite=Strict Cookie）。
- **两步验证（TOTP）**：可选开启；开启后敏感操作需密码 + TOTP。
- **敏感操作 step-up**：修改密码、注销其他会话、导出/导入备份都需再次验证。
- **账户恢复**：用一次性恢复码重置主密码；支持重设恢复码。
- **多用户**：注册、管理员（用户列表/禁用/启用/删除）；用户数据严格互相隔离。
- **加密备份导出 / 导入**：导出带导出密码的加密备份；导入覆盖当前数据（用备份的导出密码解密）。
- **审计日志**：登录、失败锁定、凭证增删改、导出、改密、恢复等，全部脱敏落盘。
- **主题切换**：深色 / 浅色，默认跟随系统，选择被记住。

## 六、技术与形态约束（便于本地 agent 复用）

- 前端：React + Vite，手写 CSS，系统字体栈，不引用外部 CDN/字体/脚本；无 PWA 之外的第三方 UI 库。
- 后端：Node ESM，运行时零第三方依赖（只用 Node 内置模块）。
- 数据模型统一为 `plan / windows / balance / error / source / fetchedAt`：订阅额度走 `windows`（各自带 usedPercent/used/total/unit/resetAt），纯余额走 `balance`。
- 绝对**不伪造额度**：拿不到分母（如余额）就不画百分比，如实显示「不可用/凭证过期/被限流/上游变更」并给原因。

---

## 七、单机版要保留 vs 砍掉（结论）

**保留**：仪表盘（额度卡/余额卡/进度切换/分组与总览/拖拽排序/自动刷新/主题）、凭证管理（增删改）、Codex 账号枚举与选择、Provider 元信息表单、自动读取本机已有工具配置（Codex `~/.codex`、OpenCode `auth.json`）+ 手动填写双轨凭证来源。

**砍掉**：注册/登录/登出/恢复、会话/TOTP/多用户/管理员/审计、导出导入备份（这些都依赖服务器账户体系）。

---

## 八、给本地 agent 的关键约束

1. **单机、离线、无账户体系**：不连接你的服务器，凭证只存本机（Windows 用系统钥匙串，Android 用系统安全存储）。
2. **复用最大化**：Provider 引擎（任一平台的取数逻辑）直接复用现有 `src/server/providers/**`；前端几乎照搬，只精简掉登录/审计/用户分支。
3. **不伪造额度、密钥不进日志、密钥不发到任何远端**。
